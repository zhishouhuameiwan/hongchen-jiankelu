# 架势博弈 V1 战斗系统设计

## 背景

当前战斗系统是回合制卡牌战斗：开战抽 3 张，玩家每回合只能打一张牌，随后立即自动结算敌人意图并进入下一回合。敌人意图按固定序列循环，状态主要用于展示和日志。这个结构清晰、易测试，但决策密度偏低，玩家常常只是在“看到攻击就格挡，看到防守就攻击”。

本设计将战斗升级为“读敌招、排出招顺序、分配行动点与内力、利用架势克制”的轻量武侠博弈。目标是显著提升战斗策略性，同时保留现有卡牌、敌人、装备、事件和奖励流程，不进行大重构。

## 目标

- 每回合有 2-3 个有意义选择，而不是只点一张最优牌。
- 敌人意图不只是伤害提示，而是影响本回合最佳应对方式。
- 玩家可以一回合打多张牌，形成小连招。
- 基础卡组也能体现博弈：劈风斩、横剑格挡、调息各有用途。
- 状态效果实际参与结算，让中毒、破绽、封脉、反击等成为可构筑元素。
- 第一版以小步 TDD 落地，保证现有主线、战斗奖励和构建不被破坏。

## 非目标

V1 不做以下内容：

- 复杂洗牌、弃牌堆、牌库循环。
- 敌人动态 AI 或学习玩家行为。
- 同时出招暗牌机制。
- 武器招式树、站位、距离、部位破坏。
- 大量新卡或完整重平衡。
- 战斗动画和复杂演出。
- 长期伤残系统。

这些可以在 V2/V3 再设计。

## 核心战斗循环

每场战斗仍是回合制卡牌战斗。

每回合开始：

- 玩家抽 4 张牌。
- 行动点 `actionPoints` 重置为 3。
- 内力继续使用现有 `innerPower / maxInnerPower`。
- 敌人展示一个明确的战术意图。

玩家回合内可以连续出牌。每张牌同时消耗：

- 行动点 `costAction`。
- 内力 `costInnerPower`。

玩家回合结束条件：

- 玩家点击“结束回合”；或
- 行动点不足以继续出牌；或
- 战斗因敌人气血归零而胜利。

出牌后不再自动结算敌人行动。只有结束回合时，才统一结算敌方意图、回合末状态、下一回合抽牌和行动点重置。

## 敌人战术意图

扩展敌人意图，新增战术字段：

```ts
type EnemyTactic = 'assault' | 'guard' | 'charge' | 'cast' | 'feint'
```

| 敌人战术 | 表现 | 推荐应对 |
| --- | --- | --- |
| `assault` 猛攻 | 高伤害攻击 | 身法、格挡、卸力 |
| `guard` 守势 | 护体、防反 | 破招，不适合普通攻击 |
| `charge` 蓄力 | 本回合准备，下回合重击或强化 | 打断、封脉、抢攻 |
| `cast` 施术 | 上毒、流血、封脉 | 打断、清心、快速压血 |
| `feint` 虚招 | 低伤害但制造破绽或诱导误判 | 稳健防守、识破、奇招 |

UI 显示格式示例：

> 敌人意图：猛攻 · 9 点伤害 · 身法可卸力

## 玩家卡牌战术标签

扩展卡牌定义：

```ts
type CombatTactic = 'attack' | 'guard' | 'movement' | 'break' | 'inner' | 'trick' | 'demonic' | 'romance'

type CardDefinition = {
  // existing fields...
  costAction?: number
  tactic?: CombatTactic
}
```

V1 默认规则：

- 缺失 `costAction` 的非装备战斗牌默认 1。
- 装备牌仍不进入战斗手牌，不需要战斗行动点。
- 缺失 `tactic` 的卡牌可按 `type` 映射：攻击为 `attack`，防御为 `guard`，身法为 `movement`，内功为 `inner`，奇招为 `trick`。

初始卡牌映射：

| 卡牌 | 战术 | 行动点 | 设计变化 |
| --- | --- | ---: | --- |
| 劈风斩 | `attack` | 1 | 基础伤害，打破绽更强 |
| 横剑格挡 | `guard` | 1 | 获得格挡，克制猛攻 |
| 调息 | `inner` | 1 | 回内力，可作为资源调度牌 |
| 流云步 | `movement` | 1 | 格挡较低，但克制猛攻 |
| 铁布衫 | `guard` | 2 | 高格挡，适合硬吃大招 |
| 青霜一剑 | `break` | 2 | 伤害并可对蓄力/施术形成打断 |
| 霜河封脉 | `break` | 2 | 打断并封脉 |
| 红莲蚀骨 | `trick` | 1 | 叠毒，适合施术和虚招窗口 |
| 夜奔 | `movement` | 1 | 大幅卸力/脱身 |
| 血河逆流 | `demonic` | 2 | 高伤害，加魔心，打破绽时爆发更强 |

## 架势克制

新增纯函数：

```ts
function getTacticMatchup(cardTactic: CombatTactic, enemyTactic: EnemyTactic): 'advantage' | 'neutral' | 'disadvantage'
```

基础克制表：

| 玩家战术 \ 敌人战术 | 猛攻 | 守势 | 蓄力 | 施术 | 虚招 |
| --- | --- | --- | --- | --- | --- |
| `attack` 攻势 | 中 | 劣 | 优 | 中 | 劣 |
| `guard` 守势 | 优 | 中 | 劣 | 中 | 中 |
| `movement` 身法 | 优 | 中 | 中 | 中 | 优 |
| `break` 破招 | 中 | 优 | 优 | 优 | 劣 |
| `inner` 内功 | 劣 | 中 | 中 | 优 | 中 |
| `trick` 奇招 | 中 | 中 | 中 | 优 | 优 |
| `demonic` 魔功 | 中 | 中 | 优 | 中 | 劣 |
| `romance` 红颜 | 中 | 中 | 中 | 优 | 中 |

V1 结算规则保持简单：

- 优势攻击：伤害 +3。
- 劣势攻击：伤害 -3，最低为 0。
- 优势防御/身法：格挡 +3。
- `break` 对 `guard`、`charge`、`cast` 优势时，额外给敌人 1 层 `vulnerable`。
- 劣势不额外惩罚资源，只通过效果变弱和日志反馈。

## 状态系统

补实当前已有状态：

| 状态 | 作用 |
| --- | --- |
| `vulnerable` 破绽 | 受到下一次伤害 +50%，触发后层数 -1 |
| `poison` 中毒 | 回合末受到层数伤害，层数 -1 |
| `bleed` 流血 | 每次出牌后受到 1 点伤害并降低 1 层 |
| `sealed` 封脉 | 通过调息获得的内力减少 1，最低为 0；触发后层数 -1 |
| `counter` 反击 | 被攻击时对攻击者造成层数伤害，触发后清除 |

状态结算边界：

- 玩家出牌造成伤害时，先处理目标 `vulnerable` 增伤，再扣血，再减少破绽层数。
- 出牌后处理玩家身上的 `bleed`。
- 敌人攻击玩家时，先被玩家 `counter` 反击，再结算敌人伤害。
- 回合末处理双方 `poison`。
- 调息类效果处理玩家 `sealed`。

## UI 设计

战斗页新增：

- 玩家气血、内力、行动点。
- 敌人意图卡：战术、数值、推荐应对。
- 每张手牌显示：
  - 行动点消耗；
  - 内力消耗；
  - 战术标签；
  - 对当前敌招的克制结果：`克制`、`普通`、`被克制`。
- 新增“结束回合”按钮。
- 日志解释关键结算，例如：
  - `流云步克制猛攻，额外获得 3 点格挡。`
  - `青霜一剑破开蓄势，敌人露出破绽。`
  - `劈风斩打在守势上，伤害降低。`

## 测试计划

按 TDD 小步推进：

1. 行动点与多出牌测试：
   - 开战行动点为 3，抽 4 张。
   - 打 1 行动点卡后行动点变 2。
   - 出牌后不自动进入下一回合。
   - 点击结束回合才结算敌人行动。
2. 克制关系测试：
   - `movement` 对 `assault` 额外获得格挡。
   - `attack` 打 `guard` 伤害降低。
   - `break` 打 `charge/cast` 施加破绽。
3. 状态生效测试：
   - `vulnerable` 增伤并降低层数。
   - `poison` 回合末造成伤害并降低层数。
   - `counter` 被攻击时反击。
   - `sealed` 降低调息收益。
4. UI 测试：
   - 战斗页显示行动点。
   - 显示敌人战术意图。
   - 卡牌显示行动点和克制状态。
   - 显示并可点击结束回合按钮。
5. 回归验证：
   - 聚焦战斗测试。
   - 全量测试。
   - 生产构建。

## 验收标准

- 玩家可以在同一回合打多张牌。
- 玩家可主动结束回合。
- 敌人意图有战术分类和应对提示。
- 至少 3 类克制关系在测试中生效。
- 至少 4 个状态实际影响战斗结算。
- 现有主线通关回归测试通过。
- 全量测试和生产构建通过。
